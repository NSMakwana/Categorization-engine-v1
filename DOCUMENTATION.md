1. Project Vision (brief)
--------------------------------------------------------------------------------
This project is a hybrid deterministic + ML transaction categorization engine for banking/financial narrations. The deterministic parser and rule layers perform structured semantic extraction; a lightweight ML model (TF-IDF + Logistic Regression) augments coverage and recall where deterministic rules are weak.

Goals achieved so far:
- Deterministic pipeline: normalization, protocol detection, protocol-aware parsing, semantic facts extraction, rule-based classification.
- ML augmentation: synthetic data generation to balance classes, TF-IDF + LogisticRegression baseline trained and saved.
- Streamlit UI for review, AI refinement integration hooks, and an 'ML Evaluation' tab to compare ML vs rule outputs.

3. Important design principles
--------------------------------------------------------------------------------
- Deterministic-first: parser and signals should extract structured evidence; AI should validate/augment, not replace.
- Token-safe matching: matcher.token_pattern uses boundary-aware regex, avoiding naive substring matches that create false positives.
- Explainability: classification outputs include decision_path, parser_rule, parser_confidence, and ranked_candidates.
- Confidence-driven routing: parser_confidence and classifier confidence should be used for hybrid decisions and review triage.

4. Normalization details
--------------------------------------------------------------------------------
File: engine/normalizer.py
Key behavior:
- Converts narration to uppercase
- Trims whitespace and collapses multiple spaces
- Standardizes separators using regex: consecutive - or / are collapsed into a single '/'
- Returns empty string for NaN

Why: maintains consistent tokenization for parser and matcher while keeping separators where meaningful.

5. Token matching & entity cleaning
--------------------------------------------------------------------------------
File: engine/matcher.py
Key functions:
- token_pattern(term): builds a boundary-aware regex using allowed TOKEN_CHARS (A-Z0-9_. now includes underscore / dot)
- regex_match(pattern, text): normalized-case regex search wrapped with metadata
- token_match/first_token_match/any_token_match helpers for rule lists
- compact_tokens(text): extracts compacted token sequences (letters, digits, underscore, dot)
- clean_entity_text(text): removes noisy fragments (VALUE DATE, NA, UPI) and trims separators

Notes: TOKEN_CHARS was expanded to include underscore and dot to prevent mis-detection around handles and compact tokens.

6. Parser: rail-specific logic and outputs
--------------------------------------------------------------------------------
File: engine/parser.py
Outputs a dictionary with keys such as:
- transaction_prefix, transaction_subtype, reference_id, entity_name, bank_name, upi_id, upi_handle
- parse_quality (LOW/MEDIUM/HIGH), parser_rule, parser_confidence, rail, family, subtype, counterparty, bank

Highlights:
- UPI parsing recognizes UPI/REV, UPI/RRN, UPI/... slash-separated formats and extracts UPI IDs using a tightened regex (A-Z0-9._+\-]{2,}@[A-Z0-9.\-]{2,}).
- IMPS, NEFT, RTGS, ACH, ATM, CHEQUE have tailored regexes and fallback generic parsing.
- parse_transaction routes to specific parsers based on token matches (UPI, IMPS, NEFT, RTGS, ACH, ATM, CHEQUE) with case-insensitive matching.

Parser confidence values are set heuristically per rule (e.g., HIGH 0.9+, MEDIUM ~0.66-0.88, LOW ~0.35-0.40).

9. ML augmentation: synthetic data & model details
--------------------------------------------------------------------------------
Script: train_and_evaluate.py (generated/used in this session)

What it does:
1. Loads the labeled CSV: D:\Nency\Mitex Intel System\Transaction Generator\output\cleaned_transactions.csv
2. Detects label column (Old Category preferred, else Category)
3. Normalizes narration if missing
4. Computes per-class counts and sets a target per-class cap (default SYNTHETIC_PER_CLASS_CAP=2000).
5. For minority classes, generates synthetic samples using token-level augmentation (token deletion, swap, separator noise, numeric noise). This creates a balanced dataset with up to cap per class; in the run, produced 68,000 rows.
6. Saves balanced CSV to: models\train_balanced.csv
7. Splits into train/val (80/20) stratified by class (converted to numpy arrays to avoid pyarrow issues).
8. Vectorizes using TfidfVectorizer(ngram_range=(1,2), min_df=2).
9. Trains LogisticRegression(max_iter=2000) on training data.
10. Evaluates on validation set and saves the pipeline (pickle) to models\tfidf_logreg_pipeline.pkl and confusion matrix to models\confusion_matrix.json.

Model details (baseline):
- Feature extractor: TF-IDF on normalized narrations, unigrams + bigrams, min_df=2
- Classifier: sklearn.linear_model.LogisticRegression, default hyperparameters except max_iter=2000
- Synthetic balancing cap: default 2000 per class (configurable in the script)

Performance observed (session run):
- On balanced validation: accuracy/precision/recall/f1 ≈ 0.995 (expectedly high due to synthetic balancing)
- On held-out real data (your run through Streamlit): Accuracy ≈ 0.9149, Precision ≈ 0.9475, Recall ≈ 0.9149, F1 ≈ 0.9210 — real-world figure to trust more than the synthetic-augmented validation

12. Integration strategies (rule vs ML)
--------------------------------------------------------------------------------
Recommended patterns:
- Fallback: run rule-based deterministic categorization first. If parser_confidence < threshold OR decision 'review_required' is true, use ML prediction as suggestion or final category.
- Override policy: prefer rule-based result if parser_confidence >= high_threshold (e.g., 0.8); else use ML. Exposed now as 'Hybrid' decision mode in the UI.
- Ensemble: combine rule-based ranked_candidates with ML top-k probabilities; use a tie-breaker based on confidence, or surface top-k to human reviewer.
- Human-in-the-loop: send mismatches / low-confidence rows to review queue and use edits to continuously improve training corpus.

15. Limitations & caveats
--------------------------------------------------------------------------------
- Synthetic augmentation is lightweight and token-level; unrealistic augmentations can lead to optimistic validation numbers. Prefer targeted, domain-aware augmentation for better generalization.
- Deterministic rules are only as comprehensive as the rule files (rules/*.json). Adding high-quality merchant aliases and protocol-specific patterns improves precision and recall together.
- The current ML model is a baseline. For production, consider:
  - Calibrated probabilities (CalibratedClassifierCV)
  - Per-class thresholds
  - Cross-validation and hyperparameter tuning
  - More advanced text embeddings (e.g., domain-tuned transformer) if needed — but weigh cost and explainability tradeoffs.
